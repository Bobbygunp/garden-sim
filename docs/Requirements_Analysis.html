1. Problem Statement

Manual gardening demands constant, uninterrupted human attention. A gardener must monitor soil moisture across multiple plant zones, regulate ambient temperature, apply fertilizer on schedule, manage pest outbreaks, and ensure adequate lighting — tasks that cannot be neglected for even a few hours without plants beginning to deteriorate. For a large garden containing many different species, each with its own ideal environmental range, this level of continuous oversight is impractical for a single person.

This project analyzes, designs, and implements a Computerized Automated Gardening System that eliminates the need for constant human supervision. The system simulates a 20×20 grid garden containing 36 plants across six species (Tomato, Rose, Sunflower, Carrot, Lettuce, and Cactus), a self-sustaining insect ecosystem, 24 environmental sensors, and 12 irrigation sprinklers. Five autonomous modules — a Watering System, Heating & Climate Control System, Pest Control System, Lighting System, and Fertigation System — monitor environmental conditions every simulation tick and respond automatically to keep every plant alive and healthy.

The system also provides a JavaFX graphical dashboard so that a human gardener can observe the garden in real time, intervene manually when desired, place new plants via a Seed Tray interface, and review a detailed audit log of every event. An external monitoring API allows a grading system to inject environmental events (rainfall, extreme temperatures, parasite outbreaks) and query the current state of every plant at any moment.

The primary success criterion is that the garden survives autonomously for 24 or more continuous hours, with all plants remaining alive throughout externally injected stress conditions, without any hardcoded cheating in the health logic.

3. Assumptions & Constraints

IDStatement
AC-01The garden grid is fixed at 20×20 cells. Each cell holds at most one entity (plant, sprinkler, or sensor).
AC-02Simulation time is discrete. One tick = 500 ms real time at 1.0× speed. One simulated day = 200 ticks.
AC-03Plant health is a continuous value from 0 to 100. A plant dies the tick its health reaches 0 or below.
AC-04All five modules execute every tick autonomously with no human trigger required.
AC-05The simulation must never crash from an unhandled exception. All runtime errors are caught and logged.
AC-06Plant health logic is realistic — plants die if their environmental needs are not met. No hardcoded immortality.
AC-07Log files are written to disk in near real time. The grading system reads them after the run ends.
AC-08The external monitoring API (GardenSimulationAPI) is the only programmatic interface for grading interactions.
AC-09Temperature values are in degrees Fahrenheit throughout the system.

4. Feature List

Garden World

  • 20×20 grid with an occupancy map — O(1) collision detection prevents two entities sharing a cell.
  • 36 plants across 6 species organized into 5 irrigation zones by row.
  • Day/night light cycle repeating every 200 ticks; light rises and falls sinusoidally.
  • Four seasons (Spring, Summer, Autumn, Winter), each lasting 1,000 ticks (~5 simulated days), with different temperature baselines and rain probabilities.
  • Probabilistic rain events that deliver water to all plants at a per-tick rate.

Plant System

  • Eight growth stages: SEED → SPROUT → VEGETATIVE → FLOWERING → FRUITING → MATURE → WILTING → DEAD.
  • Per-tick water and nutrient consumption rates set individually per species.
  • Health damage from: dehydration, overwatering, temperature stress, nutrient deficiency, nutrient burn, pest attacks, and insufficient light.
  • Health recovery of up to +2.8 HP/tick when all conditions (water, nutrients, temperature, light) are in their ideal ranges simultaneously.
  • Daily Light Integral (DLI) tracking — light accumulates over each 200-tick day and is evaluated once per cycle.
  • Species-specific pest resistance (15 %–60 %) and overwatering tolerance (40 %–80 %).

Insect Ecosystem

  • Four insect types: Aphid (pest), Caterpillar (pest), Bee (pollinator), Ladybug (beneficial predator).
  • Ecological respawning: new Aphids every 60 ticks, Caterpillars every 100 ticks, Bees every 150 ticks.
  • Ladybugs spawn conditionally when live pest count exceeds 2.
  • Natural lifespan per species; insects die of old age without pest control intervention.
  • Ladybugs actively hunt pests, providing biological control between automated pest control cycles.

Sensor Network (24 sensors)

  • 6 Moisture Sensors — zone-rectangular sensing, each linked to one watering zone.
  • 11 Temperature Sensors — 5 at grid corners and center (global), 6 zone-specific (linked to heating zones).
  • 7 Light Sensors — distributed across rows 0 and 19 plus center for full coverage.
  • All sensors trigger WARN-level log alerts when readings cross their configured thresholds.

Module 1 — Watering System

  • 12 sprinklers across 6 plant zones (SPR-1 through SPR-12).
  • Zone-aware: each sprinkler waters only plants within its linked zone rectangle — no cross-zone interference.
  • Threshold-based: activates below low threshold, deactivates above high threshold (values tuned per species).
  • Fertigation integrated: every watering cycle also delivers nutrients to each watered plant.

Module 2 — Heating & Climate Control System

  • 6 heating zones, each with a target temperature tuned to the resident species' ideal range.
  • Heating activates when zone temperature falls below target; cooling activates when above target.
  • Each active zone contributes 0.15 °F/tick of adjustment to ambient temperature.

Module 3 — Pest Control System

  • Checks pest population every 5 ticks; activates when ≥1 pest is detected.
  • Three control methods: TARGETED (pests only, default), ORGANIC (slower, safe), CHEMICAL (kills all insects).
  • TARGETED method leaves Bees and Ladybugs unharmed.

Module 4 — Lighting System

  • Activates supplemental grow lights when ambient light drops below 50 (target threshold 60).
  • Responds automatically to day/night cycle, overcast rain events, and seasonal variation in day length.

Module 5 — Fertigation System

  • Zone-aware nutrient injection every 12 ticks.
  • Per-zone injection rates calibrated to each species' nutrient consumption rate.
  • Hard cap per species prevents nutrient levels from exceeding the burn threshold (85 % for most species).

JavaFX Dashboard

  • Live 20×20 grid canvas with per-cell icons for plants, sprinklers, sensors, and insects.
  • Canvas auto-scales with window resize; zoom in/out/fit controls and keyboard shortcuts.
  • Control bar: Pause/Resume, Speed Slider (0.1×–5.0×), Manual Water, Pest Control, Fertilize All.
  • Keyboard shortcuts: SPACE (pause), ↑ / ↓ (speed ±10 %), HOME (reset zoom).
  • Seed Tray tab: select a species, click any empty cell to plant; drag existing plants to relocate them.
  • Plants, Sensors, and Modules tabs provide live-updating data tables.
  • Log Viewer: scrollable live feed of the last 500 log entries, filterable by category.

Logging System

  • Every event logged with timestamp, severity level (INFO / WARN / ERROR), and category tag.
  • 13 categories: APPLICATION, GARDEN, PLANT, INSECT, SENSOR, WATERING, HEATING, PEST_CONTROL, LIGHTING, FERTIGATION, WEATHER, USER_ACTION, API.
  • Full log written to a timestamped file in logs/; last 500 entries retained in memory for the UI.

External Monitoring API

  • initializeGarden() — creates garden from config file, plants all species.
  • rain(double mm) — injects a rainfall event for the current simulated day.
  • temperature(double F) — overrides ambient temperature for the current simulated day.
  • parasite(String name) — spawns a pest insect immediately at a random grid position.
  • sleepOneHour() — advances the simulation by one simulated hour and returns full state JSON.
  • getState() — returns a JSON snapshot of all plants, insects, sensors, and modules.

5. Use Cases — User Stories & Scenarios

UC-01 · Actor: Gardener
Start the Garden Simulation
User Story
As a gardener, I want to launch the simulation and immediately see the garden running autonomously, so that I do not have to configure anything before observing it.
Preconditions
The application is installed and the JDK 18 / JavaFX 18 environment is configured.
Main Scenario
  1. The gardener runs the application (mvn javafx:run).
  2. A splash screen appears while the garden loads in the background.
  3. The system creates the 20×20 grid, instantiates 36 plants across 6 species, 24 sensors, 12 sprinklers, 6 initial insects, and all 5 modules.
  4. The simulation engine starts at 1.0× speed without any gardener action.
  5. The dashboard appears: the canvas shows all plants as colored circles, sprinklers and sensors are visible at their grid positions.
  6. The log viewer shows initialization entries for every component.
  7. Plants begin consuming water and nutrients; modules start responding; insects begin moving — all without human input.
Postconditions
All 36 plants are alive at health 100. All 5 modules are enabled. A timestamped log file has been created in logs/.
UC-02 · Actor: Gardener
Observe Live Garden State
User Story
As a gardener, I want to see every plant's health, water, nutrients, and growth stage updated in real time, so that I understand the condition of the garden at a glance.
Preconditions
The simulation is running.
Main Scenario
  1. The gardener looks at the canvas: plant circles are color-coded by species, sized by growth stage, and grayed out when dead.
  2. The gardener clicks the Plants tab — a live table shows each plant's ID, species, health (color-coded green/orange/red/gray), water %, nutrient %, growth stage, and grid position.
  3. The gardener clicks the Sensors tab — all 24 sensors are listed with their current reading and a red alert flag if the reading is outside the safe threshold.
  4. The gardener clicks the Modules tab — each of the 5 modules shows its operational state and a running count of activations.
Postconditions
No state was changed. The gardener has a complete, current picture of the garden.
UC-03 · Actor: Gardener

User Story
As a gardener, I want to pause the simulation at any moment so that I can examine the garden state without it changing while I look.
Preconditions
The simulation is running.
Main Scenario

  5. The gardener presses SPACE again — the tick loop resumes exactly where it paused.
  6. The log records: [USER_ACTION] Simulation resumed by user.

No plant or module state was modified during the pause period.

Manually Water the Garden
User Story
As a gardener, I want to trigger an immediate full watering event so that I can respond quickly when I notice plants drying out.
Preconditions
The simulation is running. At least one plant is alive.
Main Scenario
  1. The gardener notices low water levels (orange/red) in the Plants tab.
  2. The gardener clicks Manual Water in the control bar.
  3. All 12 sprinklers activate simultaneously across every plant zone.

UC-06 · Actor: Gardener
Manually Trigger Pest Control
User Story
As a gardener, I want to manually activate pest control at any moment so that I can immediately eliminate a pest outbreak I spot on the canvas.
Preconditions
The simulation is running. At least one pest insect (Aphid or Caterpillar) is alive.
Main Scenario
  1. The gardener sees red moving dots (pests) on the canvas near plants with dropping health.
  2. The gardener clicks Pest Control in the control bar.
  3. The Pest Control module runs immediately, outside its normal 5-tick schedule.

  6. The log records: [USER_ACTION] Manual pest control triggered by user and [PEST_CONTROL] Eliminated X pests. Total eliminated: N.

Postconditions
All pest insects are dead. Plants stop receiving pest damage on the next tick.

Manually Fertilize All Plants
User Story
As a gardener, I want to immediately inject nutrients into all living plants so that I can respond quickly when I see nutrient levels falling dangerously low.
Preconditions
The simulation is running. At least one plant is alive with nutrient level below 85 %.
Main Scenario

UC-12 · Actor: Watering System
Automated Zone Irrigation
User Story
As the Watering System, I want to activate the correct zone's sprinklers when soil moisture drops below threshold so that plants never die of dehydration without human intervention.
Preconditions
At least one plant zone has soil moisture below its configured low threshold.
Main Scenario
  1. Tomatoes (rows 1–2) consume 1.2 water units per tick; zone moisture gradually drops.
  2. Moisture Sensor SENSOR-1 reads the minimum water level across all plants in the Zone 1 rectangle — it falls below the low threshold (40 %).
  3. On the next WateringSystem.update() call, SPR-1, SPR-2, and SPR-3 activate.
  4. Each active sprinkler delivers water and nutrients to every plant in the zone rectangle each tick.
  5. The log records: [WATERING] Zone SPR-1 activated at (3, 4).
  6. Zone moisture rises above the high threshold (80 %) — all three sprinklers deactivate. The log records the deactivation.
Alternative — Rain is active: Rain simultaneously raises moisture. If rain alone keeps moisture above the low threshold, the sprinklers never activate for that zone.
Postconditions
Zone 1 plant water levels are in the healthy 40–80 % range. Plants receive the +1.2 HP/tick recovery bonus from ideal hydration.
UC-13 · Actor: Heating System
Automated Climate Control
User Story
As the Heating System, I want to heat or cool each zone to its species-specific target temperature so that no plant suffers temperature stress damage.
Preconditions
At least one zone's temperature sensor is reading outside that zone's target range.
Main Scenario — Overnight heating
  1. The day/night cycle causes the ambient temperature to drop to 52 °F overnight.
  2. Temperature Sensor SENSOR-16 (Zone 5 — Lettuce, target 58 °F) reads 52 °F — below target.
  3. HZONE-5 activates heating. The log records: [HEATING] HZONE-5 HEAT ON: 52.0°F < target 58.0°F.
  4. The garden's ambient temperature rises 0.15 °F/tick until the zone reaches 58 °F.
  5. Heating turns off. The log records: [HEATING] HZONE-5 HEAT OFF: temperature 58.1°F reached target.
Alternative — Temperature spike (110 °F): All 6 zones read above their targets simultaneously. All 6 zones activate cooling, pulling the ambient temperature down at 6 × 0.15 = 0.9 °F/tick.
Postconditions
Each zone's temperature is at or near its target. Temperature-stress health damage is minimized.
UC-14 · Actor: Pest Control System
Automated Pest Elimination
User Story
As the Pest Control System, I want to automatically detect and eliminate pest insects so that plants are not continuously damaged while unattended.
Preconditions
The simulation is running. At least one pest insect is alive.
Main Scenario
  1. An Aphid spawns at tick 60 at position (3, 5).
  2. Each tick the Aphid is within 2.0 cells of a plant, it deals 0.8 damage/tick (reduced by the plant's pest resistance).
  3. Every 5 ticks, PestControl.update() counts live pests — 1 detected; threshold is 1.
  4. TARGETED pest control fires. The Aphid is eliminated. The log records: [PEST_CONTROL] 1 active pests detected. Activating TARGETED control.
  5. The log also records: [INSECT] Aphid [INSECT-5] eliminated by TARGETED pest control.
  6. Bees and Ladybugs are unaffected. Plant damage stops on the next tick.
Alternative — Ladybug predation: A Ladybug moving near the Aphid has a probability each tick of killing it before the 5-tick check fires, providing natural biological control.
Postconditions
All pest insects are eliminated. New pests will respawn ecologically after 60–100 ticks, keeping the module continuously exercised.

UC-16 · Actor: Fertigation System
Automated Nutrient Injection
User Story
As the Fertigation System, I want to inject nutrients into each zone when levels run low so that plants never starve, and stop injecting before burn thresholds are reached.
Preconditions
At least one zone has average nutrient levels below its configured low threshold.
Main Scenario
  1. Roses (rows 5–6) consume 0.4 nutrients/tick; over 12 ticks the zone average drops to 35.2 % — below the threshold of 40 %.
  2. FertigationSystem.update() fires on the 12-tick interval and identifies Zone 'Roses' as needing injection.
  3. 8.0 nutrient units are injected into each Rose in the zone. The log records: [FERTIGATION] Zone 'Roses': fertilized 3 plants (nutrients: 35.2% -> 43.2%).
  4. On the next 12-tick check, levels are above the low threshold — injection is skipped.
  5. If nutrient levels reached 85 % (cap), the system skips injection entirely. The log records: [FERTIGATION] Zone 'Roses': all plants above threshold (avg 72.4%), skipping.
Alternative — Nutrient burn: If a plant somehow exceeds 85 %, it takes -(level − 85) × 0.04 HP/tick damage each tick. The fertigation cap prevents this under normal automated operation.
Postconditions
Rose nutrient levels remain in the ideal 40–85 % range, yielding +0.5 HP/tick recovery bonus.

As the Monitoring System, I want to query the complete garden state after 24 simulated hours so that I can record how many plants survived and assess every plant's final health.

UC-21 · Actor: Garden (Automated)
Ecological Insect Lifecycle
User Story
As the garden ecosystem, insects must spawn, live, interact with plants, and die naturally so that the pest control module is continuously exercised and beneficial insects provide real biological value.
Preconditions
The simulation has been running for at least 60 ticks beyond initial setup.
Main Scenario
  1. Every 60 ticks a new Aphid spawns at a random grid position.
  2. Every 100 ticks a new Caterpillar spawns.
  3. Every 150 ticks a new Bee spawns.
  4. When the live pest count exceeds 2, a Ladybug spawns to provide biological control.
  5. Ladybugs move toward pest insects and have a per-tick probability of killing adjacent pests.
  6. Bees move toward flowering plants and pollinate them (small health bonus for flowering-stage plants).
  7. Each insect ages every tick; upon reaching its lifespan (Aphid 200, Caterpillar 250, Bee 300, Ladybug 400 ticks), it dies of old age. The log records: [INSECT] Aphid [INSECT-5] died of old age (age: 200 ticks).
Postconditions
The insect population cycles continuously throughout the simulation. The pest control module is activated on a regular schedule. Beneficial insects remain in the garden.
UC-22 · Actor: Garden (Automated)
Seasonal Environment Change
User Story
As the garden environment, the simulation must cycle through four seasons so that temperature baselines, day length, and rain probabilities change over time, continuously challenging all five automated modules.
Preconditions
The simulation has been running for at least 1,000 ticks.
Main Scenario
  1. SPRING (ticks 0–999): Moderate temperature baseline (~62 °F), moderate rain probability, growing day length. All modules operate in normal ranges.
  2. At tick 1,000 the season changes to SUMMER. Baseline rises (~75 °F), rain becomes less frequent, days lengthen. Heating System cools more; Lighting System activates for shorter nights.
  3. At tick 2,000 the season changes to AUTUMN. Baseline cools (~58 °F), rain frequency increases. Heating System activates more often.
  4. At tick 3,000 the season changes to WINTER. Low baseline (~45 °F), rare rain, short days. Heating System runs nearly continuously; Lighting System activates early each evening. Lettuce and Carrot zones (cold-tolerant) require less heating than Tomato and Sunflower zones.
  5. The log records each transition: [GARDEN] Season changed to SUMMER.
Postconditions
The garden survives all four seasons. All 5 modules adapt automatically to the seasonal environment without any human intervention.

6. Non-Functional Requirements

IDRequirement
NFR-01 Reliability: The simulation must not crash due to any unhandled exception. All runtime errors are caught at the SimulationEngine level, logged as [ERROR], and the garden continues operating.
NFR-02 Longevity: The simulation must run continuously and unattended for 24+ real-world hours with all plants surviving, under externally injected stress events.
NFR-03 UI Responsiveness: The JavaFX dashboard must remain fully responsive at all simulation speeds (0.1×–5.0×). Canvas rendering executes on the JavaFX Application Thread via AnimationTimer.
NFR-04 Log Durability: Log entries must be flushed to disk at minimum every 50 entries so that no more than ~50 entries are lost in the event of a force-quit.
NFR-05 Grid Integrity: No two entities may ever occupy the same grid cell. The occupancy grid enforces this in O(1) time on every plant placement and move operation.
NFR-06 Authentic Health Logic: Plant health must not be hardcoded to remain high. Plants die realistically if their water, nutrient, temperature, or light needs are not met by the automated modules.
NFR-07 Log Readability: Every log entry must be a single, human-readable line in the format [TIMESTAMP] [LEVEL] [CATEGORY] message, readable in any plain-text editor without special tools.
NFR-08 Module Count: The system must include a minimum of 3 standalone automated modules beyond the plants. This implementation provides 5: Watering System, Heating System, Pest Control, Lighting System, and Fertigation System.
NFR-09 Memory Safety: The in-memory log is capped at 50,000 entries to prevent unbounded RAM growth during 24+ hour runs. The file-based log retains the complete history.
NFR-10 Thread Safety: All shared collections (plants, insects, sensors, modules, log entries) use synchronized or concurrent data structures to prevent race conditions between the simulation thread and the JavaFX rendering thread.
